## Part 1 — rebrand foundation (merged: `b1b5034a`, PR #1)

Branch `chore/rebrand-foundation`, 6 atomic commits, PR
`https://github.com/dramatic4678565/mosaic/pull/1`.

### What was done

- `@mosaic/brand` single-source-of-truth package (Step 3)
- 10 brand assets regenerated from `mosaic-brand-directions.zip` (Step 4).
  The zip holds 536 SVGs; `mosaic.svg` (2×2 tile mark, `#3977df` family) was
  chosen. PNG/JPEG rasterisation is done by
  `scripts/brand/generate-assets.ps1` using `System.Drawing`, so the assets are
  reproducible without ImageMagick or sharp.
- HTML shell, meta tags and PWA manifest rebranded (Step 5a)
- 53 of 58 locale files rebranded, values only (Step 5b)
- UI component strings, main menu group, file-picker descriptions (Step 5c)
- `ExcalidrawLogo` artwork swapped, component API and CSS class names preserved
  (Step 5d)

### Decisions taken, and why

- **`Excalidraw+` kept verbatim** (asked and confirmed). It is a separate live
  paid product at `plus.excalidraw.com` that we do not own and have no `Mosaic+`
  equivalent for. 236 occurrences remain. The promo UI still points at it — worth
  revisiting in a later part.
- **`og:url` / `twitter:url` / `canonical` / `twitter:site` left pointing at
  excalidraw.com.** Deliberate attribution; revisit once `mosaic.app` exists.
- **`og:image` switched to a local asset** (`/og-image-3.png`) rather than an
  absolute excalidraw.com URL, since a Mosaic OG image now exists.
- **Logo SVG uses `currentColor` + per-tile opacity** instead of fixed brand
  hexes, so it inherits the existing `--color-logo-icon` variable and keeps
  working in dark mode. The distinct opacities are what make it read as a
  mosaic rather than a flat square.
- **The wordmark is a live `<text>` node**, not converted to paths. It inherits
  `currentColor` and the existing CSS sizing rule. Converting to outlines would
  need a font we do not have vendored.

## Part 2 — Mosaic dashboard (branch `feat/mosaic-dashboard`)

### What was built

A separate `mosaic-dashboard/` workspace app (Vite + React 19 + TS + Zustand +
Dexie + react-router 6 + dnd-kit + SCSS modules), 8 further commits.

- STEP 2 routes, one `BoardsPage` serving the four list routes
- STEP 3 board cards: thumbnail, inline rename, star, context menu
  (open/rename/duplicate/move/download .mosaic/.excalidraw/.png/.svg/trash/delete),
  multi-select, sort, search, bulk actions
- STEP 4 folders with create/rename/recolour/delete and drag-to-file
- STEP 5 activity log, timeline page, per-board stats chip
- STEP 6 editor board mode: `#board=<id>`, IndexedDB hydration, autosave
  (interval + tab-hide + unload + Ctrl+S), thumbnail capture, back link
- STEP 7 soft-delete trash, restore, delete-forever, 30-day auto-purge on boot
- STEP 8 52 vitest unit tests + one Playwright smoke test covering the whole
  lifecycle

### Decisions taken, and why

- **Dashboard is a separate app, not a route in the editor.** The editor's Vite
  config owns the whole page (PWA, service worker, asset paths); mounting a
  dashboard inside it would fight that and risk Part 1's guarantees. Keeping them
  apart also means the editor build stays literally untouched.
- **One Zustand store, not three.** Every view is a projection of the same three
  tables; a single store means a rename in the sidebar and the same rename in the
  grid cannot transiently disagree. IndexedDB stays the source of truth; the
  store is only a cache and every mutation reloads.
- **Native IndexedDB in the editor, not Dexie.** Adding Dexie to `excalidraw-app`
  would change its bundle and open a second schema-version negotiation against
  the dashboard's open connection. Opening without a version always attaches.
- **Thumbnails are JPEG, downscaled, on a white fill.** The canvas backing store
  is HiDPI-sized and transparent; a PNG at that size would eat the IndexedDB
  quota and render as a black rectangle on most dashboards.
- **Deleting a folder unfiles its boards** rather than deleting them, and
  re-parents children to the root. Tidying the sidebar must never lose work.
- **Activity rows are appended inside the mutating function** in
  `db/operations.ts`, so the audit trail cannot be bypassed by accident.
- **Stats are derived from the activity rows**, not stored as counters: the
  numbers are only ever read one board at a time, and counters would need
  keeping in sync across three code paths with no transactional benefit.

### Bugs found and fixed during the work

- `listBoards()` did not actually strip `scene` although its doc comment claimed
  it would. Caught by a unit test, fixed in the implementation rather than
  weakened in the test.
- **Portal event propagation**: `BoardCard`'s click handler fired when a menu
  item was clicked, opening the board instead of running the action. React
  portals propagate synthetic events along the React tree, not the DOM tree.
  Fixed by short-circuiting while the menu is open.
- **The board card "..." button was hover-revealed.** That is unusable on touch,
  unreachable by keyboard, and unclickable by automation (`display: none` and
  `opacity: 0` are both "hidden" to Playwright, and forcing a click lands on the
  card underneath, toggling selection). Changed to always-visible/low-contrast.
- **The editor refused to be embedded same-origin**, rendering "I'm not a
  pretzel!" — an upstream anti-clickjacking guard whose threat model is a
  user-authored scene embedding the editor. Added a narrow exception keyed on
  the `#board=` hash only.
- **Dashboard and editor were on different origins in dev**, so the IndexedDB
  handoff could never work. Added a `/editor` proxy plus
  `EXCALIDRAW_BASE_PATH` on the editor dev server. Both halves are required —
  dropping the base makes the editor emit `/App.tsx`, which 404s on the dashboard
  origin.
- **The editor dev server crashed under e2e** (exit `0xC0000409`) because
  `vite-plugin-checker` runs eslint in-process. Disabled for e2e only; linting
  still runs in CI via `yarn test:code`.
- **Root vitest was collecting the dashboard's tests** and failing them on the
  `@/` alias and missing `fake-indexeddb`. Excluded `mosaic-dashboard/**` from
  the root config; they run under `yarn test:dashboard`.
- Two of my own test assertions were wrong and were corrected rather than the
  code: `toHaveCount(0)` after filing a board in a folder (All boards shows all
  boards), and a folder-id selector that also matched `folder-name-input`.

### Verification

- editor: typecheck, eslint, prettier, build green; **141/141 test files,
  2395 tests pass**
- dashboard: typecheck green; build green; **52/52 unit tests pass**
- Playwright smoke test green in ~13 s, walking
  create → rename → favorite → move-to-folder → open editor → draw a rectangle →

- Confirmed by screenshot that the dashboard grid, folder sidebar, favourites

### Test flakiness note (carried over from Part 1)

Vitest is non-deterministic on this Windows machine. A pristine
`upstream/master` worktree with zero local changes fails a different set of tests
on each run (9, 1, 1 failures across three runs); each passes in isolation.
Do not treat these as rebrand regressions without reproducing them on the
untouched baseline first.
