## Part 1 — rebrand foundation (merged: `b1b5034a`, PR #1)

Branch `chore/rebrand-foundation`, 6 atomic commits, PR `https://github.com/dramatic4678565/mosaic/pull/1`.

### What was done

- `@mosaic/brand` single-source-of-truth package (Step 3)
- 10 brand assets regenerated from `mosaic-brand-directions.zip` (Step 4). The zip holds 536 SVGs; `mosaic.svg` (2×2 tile mark, `#3977df` family) was chosen. PNG/JPEG rasterisation is done by `scripts/brand/generate-assets.ps1` using `System.Drawing`, so the assets are reproducible without ImageMagick or sharp.
- HTML shell, meta tags and PWA manifest rebranded (Step 5a)
- 53 of 58 locale files rebranded, values only (Step 5b)
- UI component strings, main menu group, file-picker descriptions (Step 5c)
- `ExcalidrawLogo` artwork swapped, component API and CSS class names preserved (Step 5d)

### Decisions taken, and why

- **`Excalidraw+` kept verbatim** (asked and confirmed). It is a separate live paid product at `plus.excalidraw.com` that we do not own and have no `Mosaic+` equivalent for. 236 occurrences remain. The promo UI still points at it — worth revisiting in a later part.
- **`og:url` / `twitter:url` / `canonical` / `twitter:site` left pointing at excalidraw.com.** Deliberate attribution; revisit once `mosaic.app` exists.
- **`og:image` switched to a local asset** (`/og-image-3.png`) rather than an absolute excalidraw.com URL, since a Mosaic OG image now exists.
- **Logo SVG uses `currentColor` + per-tile opacity** instead of fixed brand hexes, so it inherits the existing `--color-logo-icon` variable and keeps working in dark mode. The distinct opacities are what make it read as a mosaic rather than a flat square.
- **The wordmark is a live `<text>` node**, not converted to paths. It inherits `currentColor` and the existing CSS sizing rule. Converting to outlines would need a font we do not have vendored.

### Bugs found and fixed during the work

- `scripts/brand/rebrand-locales.js` initially protected `Excalidraw-JSON`, which blocked the legitimate German compound `Excalidraw-JSON-Daten`. Removed from the protect list; re-ran and verified.
- The transliterated brand in `bn-BD` / `bn-IN` (Bengali script) would have leaked the old brand. Added transliteration handling.
- ESLint runs with `--max-warnings=0` across the whole repo, so the new scripts needed a `no-console` override (`scripts/brand/**`) and a `no-loop-func` fix.
- `verify-internals.js` reported `@excalidraw/` imports 1620 → 1621. Investigated: the delta was a _doc comment_ mentioning the import path, not an import. The check now matches `from "@excalidraw/` (code) instead of the bare token.

### Verification

- typecheck, eslint, prettier, `yarn build` all green
- 3 snapshot mismatches were pure branding and were regenerated; the diffs contain nothing but the brand change and the new logo geometry
- Headless-Chrome render of the production build: title, h1 and OG tags all Mosaic; a scan of all 119 built files for user-visible "Excalidraw" prose returns 10 hits, every one a `console.warn`/dev invariant
- `node scripts/brand/verify-internals.js` → PASS; LICENSE files byte-identical

### Not done

**Docker was never run.** Docker Desktop is not installed, WSL2 virtualization is disabled, and the session is not elevated — installing it needs admin plus a reboot, which I cannot do from a tool call. Everything else was verified natively (yarn build + a static server + headless Chrome). This is the one open item from Part 1's definition of done.

## Part 2 — Mosaic dashboard (branch `feat/mosaic-dashboard`)

### What was built

A separate `mosaic-dashboard/` workspace app (Vite + React 19 + TS + Zustand + Dexie + react-router 6 + dnd-kit + SCSS modules), 8 further commits.

- STEP 2 routes, one `BoardsPage` serving the four list routes
- STEP 3 board cards: thumbnail, inline rename, star, context menu (open/rename/duplicate/move/download .mosaic/.excalidraw/.png/.svg/trash/delete), multi-select, sort, search, bulk actions
- STEP 4 folders with create/rename/recolour/delete and drag-to-file
- STEP 5 activity log, timeline page, per-board stats chip
- STEP 6 editor board mode: `#board=<id>`, IndexedDB hydration, autosave (interval + tab-hide + unload + Ctrl+S), thumbnail capture, back link
- STEP 7 soft-delete trash, restore, delete-forever, 30-day auto-purge on boot
- STEP 8 52 vitest unit tests + one Playwright smoke test covering the whole lifecycle

### Decisions taken, and why

- **Dashboard is a separate app, not a route in the editor.** The editor's Vite config owns the whole page (PWA, service worker, asset paths); mounting a dashboard inside it would fight that and risk Part 1's guarantees. Keeping them apart also means the editor build stays literally untouched.
- **One Zustand store, not three.** Every view is a projection of the same three tables; a single store means a rename in the sidebar and the same rename in the grid cannot transiently disagree. IndexedDB stays the source of truth; the store is only a cache and every mutation reloads.
- **Native IndexedDB in the editor, not Dexie.** Adding Dexie to `excalidraw-app` would change its bundle and open a second schema-version negotiation against the dashboard's open connection. Opening without a version always attaches.
- **Thumbnails are JPEG, downscaled, on a white fill.** The canvas backing store is HiDPI-sized and transparent; a PNG at that size would eat the IndexedDB quota and render as a black rectangle on most dashboards.
- **Deleting a folder unfiles its boards** rather than deleting them, and re-parents children to the root. Tidying the sidebar must never lose work.
- **Activity rows are appended inside the mutating function** in `db/operations.ts`, so the audit trail cannot be bypassed by accident.
- **Stats are derived from the activity rows**, not stored as counters: the numbers are only ever read one board at a time, and counters would need keeping in sync across three code paths with no transactional benefit.

### Bugs found and fixed during the work

- `listBoards()` did not actually strip `scene` although its doc comment claimed it would. Caught by a unit test, fixed in the implementation rather than weakened in the test.
- **Portal event propagation**: `BoardCard`'s click handler fired when a menu item was clicked, opening the board instead of running the action. React portals propagate synthetic events along the React tree, not the DOM tree. Fixed by short-circuiting while the menu is open.
- **The board card "..." button was hover-revealed.** That is unusable on touch, unreachable by keyboard, and unclickable by automation (`display: none` and `opacity: 0` are both "hidden" to Playwright, and forcing a click lands on the card underneath, toggling selection). Changed to always-visible/low-contrast.
- **The editor refused to be embedded same-origin**, rendering "I'm not a pretzel!" — an upstream anti-clickjacking guard whose threat model is a user-authored scene embedding the editor. Added a narrow exception keyed on the `#board=` hash only.
- **Dashboard and editor were on different origins in dev**, so the IndexedDB handoff could never work. Added a `/editor` proxy plus `EXCALIDRAW_BASE_PATH` on the editor dev server. Both halves are required — dropping the base makes the editor emit `/App.tsx`, which 404s on the dashboard origin.
- **The editor dev server crashed under e2e** (exit `0xC0000409`) because `vite-plugin-checker` runs eslint in-process. Disabled for e2e only; linting still runs in CI via `yarn test:code`.
- **Root vitest was collecting the dashboard's tests** and failing them on the `@/` alias and missing `fake-indexeddb`. Excluded `mosaic-dashboard/**` from the root config; they run under `yarn test:dashboard`.
- Two of my own test assertions were wrong and were corrected rather than the code: `toHaveCount(0)` after filing a board in a folder (All boards shows all boards), and a folder-id selector that also matched `folder-name-input`.

### Verification

- editor: typecheck, eslint, prettier, build green; **141/141 test files, 2395 tests pass**
- dashboard: typecheck green; build green; **52/52 unit tests pass**
- Playwright smoke test green in ~13 s, walking create → rename → favorite → move-to-folder → open editor → draw a rectangle → Ctrl+S → back → thumbnail visible → trash → restore
- Confirmed by screenshot that the dashboard grid, folder sidebar, favourites count and the trash page all render with Mosaic branding

### Test flakiness note (carried over from Part 1)

Vitest is non-deterministic on this Windows machine. A pristine `upstream/master` worktree with zero local changes fails a different set of tests on each run (9, 1, 1 failures across three runs); each passes in isolation. Do not treat these as rebrand regressions without reproducing them on the untouched baseline first.

## Part 3 � self-maintaining infrastructure (branch `chore/self-maintaining-infra`)

Parts 1 and 2 merged (PR #1 `b1b5034a`, PR #2 `d181d39d`). Part 3 makes the repo maintain itself.

### Built

- **STEP 1** upstream sync: `scripts/sync-upstream.sh` + `.ps1`, both reading `scripts/sync-upstream.policy.json` so they cannot drift. Policy written up in `UPSTREAM_SYNC.md`.
- **STEP 2** `.github/workflows/upstream-sync.yml`: daily cron (03:17 UTC, off the hour to avoid the thundering herd) plus `workflow_dispatch` with a dry-run input. Opens a PR; never auto-merges.
- **STEP 3** `.github/workflows/ci.yml`: typecheck, lint, format, unit tests for both workspaces, rebrand guard, both builds, Playwright, artifact upload.
- **STEP 4** root `Dockerfile` (node:20 build -> nginx:1.27-alpine) serving `/` = dashboard and `/app/` = editor, plus `docker-compose.yml` on :8080 and `docker.yml` publishing to GHCR on `v*`.
- **STEP 5** QA suite: 25 Playwright specs in four files, now run against **pre-built** bundles served by `e2e/preview-server.mjs`.
- **STEP 6** README (rewritten), CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, NOTICE.

### Decisions

- **e2e runs against built output, not two dev servers.** Two dev servers exhausted RAM on a 16 GB machine and the editor dev server died mid-run, producing a wall of `ERR_CONNECTION_REFUSED`. Testing built output also means the suite exercises the real asset graph and base paths -- so a base-path bug, which is the class of bug the suite exists to catch, cannot hide.
- **A Node build wrapper instead of inline env vars.** `FOO=bar yarn build` is POSIX-only and silently wrong in cmd.exe, and this repo has no `cross-env`.
- **The rebrand audit reads rendered text, not raw HTML.** The codebase still legitimately contains the token in ~200 CSS classes, data attributes and `@excalidraw/*` package names; flagging those would fail on a correct codebase and the audit would get switched off.

### Real bugs found and fixed

1. **Board scene persistence was broken.** `appState.collaborators` is a `Map`; `JSON.stringify` flattens it to `{}`. Saving a board therefore wrote a corrupt value and reopening it crashed the editor with `e.appState.collaborators.forEach is not a function`. Draw, save, close, reopen -- broken. Fixed on both sides in `boardMode.ts`.
2. **The editor's PWA service worker was registered even when embedded.** Once activated its precache manifest began answering requests for a subsequent load and the editor rendered an empty root with no error. Now skipped when framed or in board mode.
3. **Production base-path mismatch.** The Dockerfile serves the editor at `/app/` while the dashboard hardcoded `/editor/` -- the iframe would have been blank in production. Both sides are now configurable and agree by construction.
4. **BoardPage could give the editor a zero-height viewport** via a `height: 100%` chain, and the editor never recovered. Explicit `minHeight` on both container and iframe.
5. `settings.usage` rendered "1 boards" -- the noun was both in the template and in the `pluralize()` argument.

### Harness bugs (not product bugs)

- `path.normalize` on a URL pathname rewrites slashes on Windows, so the editor branch of the preview server never ran.
- `indexedDB.deleteDatabase` is blocked by Dexie's open connection, so test data leaked between specs.
- Aborting external font requests cascaded an abort into the editor's own in-flight module preloads.
- `verify-internals.js` reported drift on correct work (documentation has to name the tokens it forbids renaming; new code adds mentions). The rule is now `after >= before` and comments are stripped.

### Not done

**Docker was still never run locally** -- Docker Desktop is not installed on this machine, WSL2 virtualization is disabled and the session is not elevated. The Dockerfile, compose file and workflow are written and the image build is exercised by CI on the `v*` tag, but no local `docker build` was executed. Stated plainly here and in the PR rather than implied to be verified.
